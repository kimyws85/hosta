# 프로젝트: AI 기반 SNS 마케팅 영상콘텐츠 제작 과정 - 수업 자료 뷰어

## 개요
강사가 수업 중 브라우저로 열어서 참고하며 진행하는 **정적 웹페이지 수업자료**.
- 순수 HTML/CSS/JS만 사용 (프레임워크, 빌드도구, 서버 없음)
- `index.html`을 더블클릭해서 바로 여는 방식으로 동작해야 함 (file:// 프로토콜에서도 정상 작동)
- 인터넷 연결 불필요 (외부 CDN, 폰트, 라이브러리 불러오기 금지 — 전부 인라인/로컬로 포함)

## 화면 흐름 (요구사항)
1. **첫 화면 = 목차**: 교과목(NO 1~8) 목록을 보여줌 (교과목명 + 총 시간)
2. **교과목 클릭** → 해당 교과목의 **세부단원 목록**이 펼쳐짐/전환됨 (단원명 + 시간을 나란히 표시)
3. **세부단원 클릭** → 그 단원에서 실제로 **수업할 내용**을 보여주는 화면으로 이동
   - 시간(몇 시간짜리 단원인지)이 항상 옆/상단에 표시되어야 함 (진행 중에도 몇 시간 분량인지 계속 확인 가능해야 함)
4. 뒤로가기(목차/교과목 목록으로 복귀) 네비게이션 필요

## 파일 구조 (예정)
- `index.html` — 마크업 뼈대 + 목차/단원/상세 3단계 화면(뷰) 컨테이너
- `style.css` — 전체 스타일
- `data.js` — 위 표를 그대로 옮긴 커리큘럼 데이터 (교과목 → 단원 배열, 각 단원에 `hours`와 `content`(수업할 내용) 필드)
- `script.js` — 목차→단원→상세 화면 전환 로직, 렌더링

## 데이터 모델 설계
```js
// data.js
const CURRICULUM = [
  {
    no: 1,
    subject: "AI 기본 및 활용",
    hours: 6,
    units: [
      {
        name: "AI 윤리 및 HITL 기반 검증",
        hours: 2,
        content: [] // 강사가 채울 실제 수업 내용 (여기가 비어있는 부분)
      },
      // ...
    ]
  },
  // ...
];
```
- `content`는 처음에는 비어있거나 최소 placeholder만 있는 상태로 시작 → **실제 수업 콘텐츠(설명, 예제, 실습 안내 등)는 강사(사용자)와 함께 이후 단계에서 단원별로 채워 넣어야 함**. 이번 단계는 틀(뷰어) 구축이 우선.

## 스타일/UX 방향
- 강사가 수업 중 훑어보는 용도이므로 가독성 우선: 큰 글자, 명확한 대비, 클릭 영역 넉넉하게
- 시간(h) 정보는 항상 시각적으로 눈에 띄게 (배지/태그 형태 등)
- 현재 위치(어느 교과목 > 어느 단원인지) breadcrumb 형태로 표시
- 반응형까지는 필수 아님 (강사 PC/노트북 화면 기준으로 우선 최적화), 다만 무리한 고정폭은 피함

## 향후 작업 순서
1. `data.js`에 위 표 전체 데이터 입력 — 완료
2. `index.html`/`style.css`/`script.js`로 목차 → 교과목 → 단원 → 상세 네비게이션 뼈대 구현 — 완료
3. 강사와 함께 교과목 순서대로(1번부터) 단원별 실제 수업 내용(`content`)을 하나씩 채워 넣기 — 진행 중

## 단원 콘텐츠(content) 제작 워크플로우
교과목을 하나씩 순서대로 진행한다 (예: 1번 교과목부터). 한 단원을 채울 때마다 아래 순서를 반복한다. (아코디언 도입 이후 "단원당 에이전트 1개"에서 "**단원의 최상위 섹션(law/checklist/case 등)당 에이전트 1개**"로 세분화됨 — 섹션 하나하나를 훨씬 깊게 파야 하기 때문.)

1. **병렬 리서치**: 한 단원 안의 최상위 섹션 개수만큼 `Agent`(subagent_type: general-purpose, 웹서치 가능, `run_in_background: true`)를 **한 메시지에서 동시에** 실행한다. (예: 6개 섹션짜리 단원 → 에이전트 6개를 병렬 백그라운드로)
2. **깊이·분량 지시**: 각 에이전트에게 "아코디언이라 기본 접혀 있으니 시간 제약 없이 깊게 써도 된다"는 것과, 최소 6~9개의 하위주제(##)로 나누고 필요하면 그 안에 또(###) 나누라고 명시한다. 기초 정의·구체적 수치(보호기간, 과태료 금액 등)부터 다루게 하고, 결론만 나열하지 않게 한다.
   - 이 과정 수강생은 SNS·영상 마케팅 실무자/취업준비생(비전공 초급자)이라는 점은 항상 알려주되, "초급자용이니 얕게 써라"가 아니라 "초급자도 이해할 수 있게 쉬운 말로, 대신 깊이 있게 써라"로 지시한다.
   - 출력 형식은 마크다운 헤딩(##, ###)+불릿(-)으로 받고, 마지막에 "참고 출처"를 반드시 받는다 — 이 출처는 화면에는 안 띄우고 `data.js`에 주석으로만 남긴다(법령 수치 등은 원문 재확인 권장 문구와 함께).
3. **검토 및 스키마 변환**: 에이전트가 만든 마크다운 아웃라인을 그대로 붙여넣지 않고, `##`→최상위 `children` 노드, `###`→그 안의 또 `children`, 불릿→`items`로 직접 변환하며 검토한다 — 이 과정 톤/난이도에 안 맞는 부분, 다른 섹션과 겹치는 부분을 다듬는다.
4. **반영 및 확인**: 변환한 트리를 `data.js`의 해당 블록 `children`에 반영한다. **브라우저 스크린샷 확인은 사용자가 직접 하므로, 명시적으로 요청받지 않는 한 매번 Chrome 자동화로 캡처하며 검증하지 않는다** — `node --check data.js` 등으로 문법만 빠르게 검증하고 넘어간다.

## 화면 구조 — 아코디언(트리 펼치기) 방식으로 확정
단원 상세 화면은 pill 이동식이 아니라 **네이티브 `<details>/<summary>` 기반 아코디언**으로 구현되어 있다 (`script.js`의 `renderNode` 재귀 함수).
- 최상위 블록(`goals`/`concept`/`law`/`checklist`/`case`)만 타입 아이콘·배지·색을 갖고, 그 아래 `children`은 들여쓰기·글자 크기 축소로만 깊이를 표시한다 (지나치게 알록달록해지는 것을 방지).
- `children`은 몇 단계든 재귀적으로 중첩 가능하다 — 실제로 "AI 윤리 및 HITL 기반 검증" 단원은 depth 3까지 내려가며 총 100개 이상의 노드로 확장되어 있다(예시 참고).
- 콘텐츠 분량 기준이 기존 "배정 시간(hours)에 맞춰 압축"에서 **"아코디언은 기본 접힘 상태이므로 시간 제약 없이 깊고 풍부하게 써도 된다"**로 바뀌었다. 대신 각 최상위 항목의 **제목만 봐도 그 안에 뭐가 있는지 짐작 가능**해야 한다.
- 리서치 단계에서 얕은 요약(정의 없이 결론만)을 내면 안 되고, 기초 정의·구체적 수치(보호기간 몇 년, 과태료 금액 등)·실제 사례까지 포함해야 한다 — "저작권이 뭔지도 없이 결론만 있다"는 피드백을 받은 적이 있다.

## 단원 콘텐츠(content) 데이터 스키마
`content`는 단순 문자열 배열이 아니라 **성격별로 분류된 구조화된 블록 배열**로 채운다. 그냥 다 "section"으로 뭉치지 말고, 아래 타입 중 내용 성격에 맞는 걸 골라서 분류해야 한다 — 이게 곧 화면에서 서로 다른 색/아이콘으로 구분되어 보기 좋게 렌더링되는 근거가 된다.

```js
content: [
  { type: "goals", title: "학습 목표", items: ["...", "..."] },
  { type: "concept", title: "핵심 개념 제목", items: ["...", "..."] },
  { type: "law", title: "법·규정 관련 제목", items: ["...", "..."] },
  {
    type: "checklist",
    title: "체크리스트 제목",
    description: "체크리스트 앞에 붙는 한 줄 설명 (선택)",
    items: ["체크포인트1", "체크포인트2"]
  },
  { type: "case", title: "실무 사례 제목", items: ["...", "..."] }
]
```

| type | 용도 | 렌더링 |
|---|---|---|
| `goals` | 그 단원의 학습 목표 (보통 첫 블록) | 강조 카드 + ✓ 아이콘 |
| `concept` | 일반 개념·이론 설명 | 기본 카드 + 💡 아이콘 |
| `law` | 법률·규정·정책 등 컴플라이언스 관련 내용 | 주의 강조(황색 톤) 카드 + ⚖️ 아이콘 — 시간 지나면 바뀔 수 있는 내용이라는 신호 |
| `checklist` | 실무에서 체크해야 할 항목 나열 | 체크박스형 리스트 + ✅ 아이콘, `description`으로 도입 설명 한 줄 추가 가능 |
| `case` | 실제/가상 사례, 시나리오 | 인용 카드 스타일 + 📌 아이콘 |

- 레거시 호환: 예전에 쓰던 `type: "section"`은 `concept`처럼, `type: "example"`은 `case`처럼 렌더링된다 (아직 재분류 못한 단원도 깨지지 않음).
- 각 블록은 `description`(선택, 목록 위에 오는 한 줄 설명)과 `items`(불릿/체크 목록)를 가질 수 있다.
- 첫 블록은 항상 `goals` 타입의 "학습 목표"로 시작한다.
- 단원 콘텐츠를 채울 때는 단순 나열이 아니라 "이 불릿이 개념 설명인지/법규인지/체크리스트인지/사례인지"를 항상 먼저 판단하고 그에 맞는 type을 골라 분류한다.
